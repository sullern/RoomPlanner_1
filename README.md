## 2. 项目简介

RoomPlanner 是一个基于 C++ 的房间物品自动摆放系统。给定房间轮廓、门的位置、待摆放物品列表，系统自动计算每个物品的摆放位置和旋转角度，满足以下约束：

- ✅ 物品完全在房间内部
- ✅ 物品之间不重叠
- ✅ 内开门不占用物品空间
- ✅ 冰箱开门边不被遮挡

适用于室内布局规划、仓储物品排布、设备间摆放等场景。

## 4. 核心数据结构

### 4.1 Point —— 二维点

```cpp
struct Point {
    double x;  // x 坐标
    double y;  // y 坐标
};
```

所有几何运算的基础单位，房间轮廓顶点、门的端点、物品中心点都是 Point。

### 4.2 Rect —— 轴对齐矩形

```cpp
struct Rect {
    double centerX;   // 中心点 x
    double centerY;   // 中心点 y
    double width;     // 宽度（x 方向）
    double height;    // 高度（y 方向）
    double angle;     // 旋转角度（0° 或 90°）
    std::string itemName;  // 对应物品名称
};
```

**设计说明**：虽然有 `angle` 字段，但算法仅支持 **0° 和 90°** 两种角度，本质上是轴对齐矩形。90° 旋转等价于交换 width 和 height。

### 4.3 Item —— 待摆放物品

```cpp
enum class ItemType {
    Fridge,      // 冰箱
    Shelf,       // 货架
    OverShelf,   // 离地架
    IceMaker     // 制冰机
};

struct Item {
    std::string name;     // 物品名称
    double length;        // 长度
    double width;         // 宽度
    ItemType type;        // 物品类型

    double centerX;       // 摆放结果：中心点 x
    double centerY;       // 摆放结果：中心点 y
    double angle;         // 摆放结果：旋转角度
};
```

输入是 `length` 和 `width`，输出是 `centerX`、`centerY`、`angle`。

### 4.4 BoundingBox —— 轴对齐包围盒

```cpp
struct BoundingBox {
    double minX;  // 最左 x
    double maxX;  // 最右 x
    double minY;  // 最下 y
    double maxY;  // 最上 y
};
```

一个刚好把多边形装进去的、边和坐标轴平行的长方形，用于缩小搜索范围。

## 5. 核心算法详解

### 5.1 整体策略：贪心 + 网格搜索

#### 5.1.1 贪心策略

**物品按面积从大到小排序，依次摆放。**

- 大件难放，先给它找位置
- 小件灵活，见缝插针
- 如果先放小件，大件可能最后塞不进去

```
先放大件，再塞小件        先放小件，大件放不下
┌───────────┐             ┌───────────┐
│  ███████  │             │  ▓ ▓ ▓ ▓  │
│  ███████  │             │  ▓ ▓ ▓ ▓  │
│           │             │  ████████ │ ← 塞不下了！
│  ▓ ▓ ▓    │             │  ████████ │
└───────────┘             └───────────┘
```

#### 5.1.2 网格搜索

**把房间平面按固定步长切成网格，物品中心点从左下角开始逐个网格点尝试放置。**

- 搜索范围：房间的包围盒内部
- 搜索顺序：从左到右、从下到上
- 找到第一个可行位置 → 放置，继续下一个物品

```
    ┌───────────────────┐
    │  ...  ...  ...    │  ↑
    │  ...  ...  ...    │  │ 往上走
    │  ...  ...  ...    │  │
    │  →→→→→→→→→→→      │  ← 从左往右扫
    │  起点              │
    └───────────────────┘
```

#### 5.1.3 两阶段角度尝试

每个物品依次尝试两个旋转角度：

1. **先试 0°**（原始方向，length 沿 x 轴，width 沿 y 轴）
2. **0° 都不行 → 试 90°**（旋转 90°，length 沿 y 轴，width 沿 x 轴）

找到第一个可行角度和位置就放置，不继续搜索更优解。

### 5.2 几何计算模块（Geometry）

几何计算是整个项目的基石，摆放算法的每一步判断都依赖它。

#### 5.2.1 pointInPolygon —— 点在多边形内（射线法）

**作用**：判断一个点在多边形内部还是外部。

**算法：射线法（奇偶规则）**

从点向右水平发射一条射线，统计它穿过多边形边的次数：
- 奇数次 → 点在内部
- 偶数次 → 点在外部

```
         射线 →→→→→→→→→
              ╱    ╲
             ╱      ╲
    ●───────╱────────╲─────  ← 穿过 2 次（偶数）→ 在外面
           ╱          ╲
          ╱    ●       ╲   ← 穿过 1 次（奇数）→ 在里面
         ╱              ╲
```

**判断条件**：
1. 点的 y 坐标在边的两个端点之间（射线穿过边的高度范围）
2. 射线与边的交点在点的右侧

**用途**：所有"包含关系"判断的基础。

---

#### 5.2.2 getCorners —— 获取矩形四个角点

**作用**：把"中心点+宽高"表示的矩形转换成四个顶点坐标。

```
    左上角 ─────── 右上角
      │             │
      │   中心点    │
      │     ●      │
      │             │
    左下角 ─────── 右下角
```

**用途**：很多几何算法需要顶点坐标，用这个函数做格式转换。

---

#### 5.2.3 getBoundingBox —— 求多边形包围盒

**作用**：找出一个刚好把整个多边形装进去的轴对齐长方形。

**算法**：遍历所有顶点，找出 minX、maxX、minY、maxY 四个极值。

```
         maxX
           │
    ┌──────┼───┐ ← maxY
    │      │   │
    │  ╭───╯   │
    │  │ 多边形 │
    │  ╰───╮   │
    │      │   │
    └──────┼───┘ ← minY
           │
         minX
```

**用途**：缩小搜索范围，减少不必要的计算。

---

#### 5.2.4 lineIntersect —— 线段相交检测（跨立实验）

**作用**：判断两条线段是否相交（不包括端点接触）。

**算法：跨立实验（叉积法）**

如果两条线段相交，那么每条线段的两个端点都分别在另一条线段的两侧。

```
    a1          b1
     ╲         ╱
      ╲       ╱
       ╳─────  ← 相交
      ╱       ╲
     ╱         ╲
    b2          a2
```

**叉积的意义**：判断一个点在一条直线的左侧还是右侧。
- 叉积 > 0 → 点在左侧
- 叉积 < 0 → 点在右侧
- 叉积 = 0 → 点在线上

**判断条件**：
- b1 和 b2 在 a 线段的两侧（叉积乘积 < 0）
- a1 和 a2 在 b 线段的两侧（叉积乘积 < 0）
- 同时满足 → 相交

**用途**：判断矩形是否穿出多边形墙壁、矩形和多边形是否重叠。

---

#### 5.2.5 rectInsidePolygon —— 矩形完全在多边形内

**作用**：判断矩形是否完全在多边形内部，没有任何部分露在外面。

**算法：两道检查**

**检查 1：四个顶点都在多边形内部**
- 调用 `pointInPolygon` 检查四个角点
- 有一个角在外面 → 不在内部

**检查 2：矩形的边与多边形的边都不相交**
- 矩形 4 条边 × 多边形 N 条边，两两检查
- 有一对相交 → 矩形穿出了墙壁 → 不在内部

```
完全在内部 ✓                四个角都在内部但边穿出 ✗
    ╭─────────────╮            ╭─────────────╮
    │  多边形      │            │  多边形      │
    │             │            │             │
    │   ╭───╮     │            │   ╭───╮     │
    │   │矩形│     │            │   │ █ █ █ █ │
    │   ╰───╯     │            │   ╰───╯     │
    ╰─────────────╯            ╰─────────────╯
```

**为什么需要两道检查？**

对**凹多边形**，只检查四个角是不够的——矩形的边可能从凹进去的地方穿出去，但四个角还在里面。加上"边不相交"的检查，就能覆盖这种情况。

**用途**：摆放时的第一道检查——物品必须完全在房间内部。

---

#### 5.2.6 rectOverlap —— 两个矩形重叠检测

**作用**：判断两个轴对齐矩形是否有重叠区域。

**算法：排除法**

反过来想，什么时候两个矩形**不重叠**？只有 4 种情况：
1. a 在 b 左边
2. a 在 b 右边
3. a 在 b 下边
4. a 在 b 上边

这 4 种都不满足 → 重叠。

```
不重叠（a在b左边）      重叠
┌───┐  ┌───┐         ┌───────┐
│ a │  │ b │         │ a ┌───┼───┐
└───┘  └───┘         └───┼───┘   │
                         │   b   │
                         └───────┘
```

**用途**：摆放时的第三道检查——新物品不能和已放置物品重叠。

---

#### 5.2.7 rectOverlapPolygon —— 矩形与多边形重叠检测

**作用**：判断矩形和多边形是否有重叠部分（只要有一点点碰到就算）。

**和 rectInsidePolygon 的区别**：
- `rectInsidePolygon`：矩形完全在多边形内部（子集关系）
- `rectOverlapPolygon`：矩形和多边形有交集就行（部分重叠也算）

**算法：三种情况满足一种就算重叠**

1. **矩形顶点在多边形内** → 重叠
2. **多边形顶点在矩形内** → 重叠
3. **矩形边与多边形边相交** → 重叠

```
情况1：矩形角在多边形内    情况2：多边形顶点在矩形内    情况3：边相交
    ╭──────╮                  ╭──────╮                ╭──╮
    │  ╭───┼──╮               │  ╭───╯                │  │
    │  │ █ │  │               │  │  ╭──╮          ╱╲  │  │
    │  ╰───┼──╯               ╰──┼──╯  │         ╱  ╲ ╰──╯
    ╰──────╯                     ╰─────╯        ╱    ╲
```

三种情况都检查到，保证不遗漏。

**用途**：摆放时的第二道检查——物品不能和门占用区域重叠。

### 5.3 摆放管理器（PlacementManager）

#### 5.3.1 核心流程

```
物品进来
  ↓
按面积从大到小排序
  ↓
取出第一个物品
  ↓
试角度 0°
  ↓
从左下角开始，遍历所有网格点
  ↓
每个点调用 canPlace 检查 4 道关卡
  ↓
找到可行位置 → 放置 → 下一个物品
  ↓
0° 都不行 → 试 90°
  ↓
90° 也不行 → 摆放失败
```

#### 5.3.2 canPlace —— 四道关卡

每个候选位置都要过 4 道检查，全部通过才能放：

| 关卡 | 检查内容 | 调用函数 | 说明 |
|------|----------|----------|------|
| 第 1 关 | 物品完全在房间内部 | `rectInsidePolygon` | 不能穿出墙壁 |
| 第 2 关 | 不与门占用区域重叠 | `rectOverlapPolygon` | 不能挡门 |
| 第 3 关 | 不与已放置物品重叠 | `rectOverlap` | 物品之间不能打架 |
| 第 4 关 | 不挡住冰箱开门边 | `checkFridgeConstraint` | 冰箱门前要留空 |

**检查顺序很重要**：把快的检查放前面，慢的放后面，提前失败就能跳过后面的计算，提升效率。

### 5.4 特殊约束处理

#### 5.4.1 内开门占用空间

**问题**：内开门会占据 1×1 的室内空间，物品不能放在那里。

**解决方案**：把门的占用区域当成一个障碍物多边形，摆放时自动避开。

**生成门障碍物的步骤**：

```
1. 取门的两个端点 p0、p1
2. 计算门的两个法向量（垂直于门的两个方向）
3. 判断哪个法向量指向房间内部：
   - 取门的中点，沿法向量移动一小步
   - 用 pointInPolygon 判断这个点在不在房间里
   - 在房间里 → 这就是内侧法向量
4. 沿内侧法向量延伸 1000mm（对应 1×1 空间）
5. 生成一个矩形障碍物多边形
```

```
        门占用区域
    ┌───────────────┐
    │               │  ← 深度 1000mm
────┴───────────────┴────
        门本身（墙上的缝）
```

**用途**：内开门时，门的摆动区域不能放东西。

---

#### 5.4.2 冰箱开门边约束

**问题**：冰箱的开门边不能放任何东西，否则门打不开。

**解决方案**：每次放新物品时，检查所有已放置的冰箱，如果新物品贴在冰箱的开门侧且间隙太小，就不让放。

**默认约定**：
- 0° 时，开门边在**顶部**（y 轴正方向）
- 90° 时，开门边在**右侧**（x 轴正方向）

```
0° 冰箱：开门边在顶部        90° 冰箱：开门边在右侧
    ┌──────────┐                 ┌──────┐
    │  开门边  │ ↑               │      │ →
    ├──────────┤                 │ 冰箱 │
    │   冰箱   │                 │      │
    │          │                 │      │
    └──────────┘                 └──────┘
```

**间隙阈值**：默认 1mm，可根据实际需求调整。

4. 点击"生成"即可

g++ -std=c++17 main.cpp JsonLoader.cpp Geometry.cpp PlacementManager.cpp \
    -o room_placement \
    -I/path/to/nlohmann/json/include

1. 将 JSON 输入文件（如 `example1.json`）放在可执行文件同级目录
2. 执行程序：

```bash
# Linux / macOS
./room_placement

# Windows
room_placement.exe
```

3. 程序会在控制台输出摆放结果

## 7. 输入输出格式

### 7.1 输入格式（JSON）

```json
{
    "boundary": [
        [x1, y1], [x2, y2], ..., [xN, yN]
    ],
    "door": [
        [x1, y1], [x2, y2]
    ],
    "isOpenInward": true / false,
    "algoToPlace": {
        "物品名1": [length, width],
        "物品名2": [length, width],
        ...
    }
}
```

| 字段 | 类型 | 说明 |
|------|------|------|
| `boundary` | 二维数组 | 房间轮廓顶点坐标，首尾相连，顺时针或逆时针均可 |
| `door` | 二维数组 | 门的两个端点坐标 |
| `isOpenInward` | 布尔值 | 是否内开门。true 表示内开，会生成门占用障碍物 |
| `algoToPlace` | 对象 | 待摆放物品列表。key 是物品名，value 是 [长, 宽] |

**物品类型识别规则**（根据名称自动匹配）：
- 名称包含 `fridge` → 冰箱
- 名称包含 `iceMaker` → 制冰机

## 9. 可调参数说明

| 参数 | 位置 | 默认值 | 说明 |
|------|------|--------|------|
| `SEARCH_STEP` | `PlacementManager.cpp` 的 `tryPlace` 函数 | 50.0 | 搜索步长（单位：mm）。越小精度越高，速度越慢 |
| `MIN_GAP` | `PlacementManager.cpp` 的 `checkFridgeConstraint` 函数 | 1.0 | 冰箱开门边最小间隙（单位：mm）。小于此值视为挡住了开门边 |
| `DOOR_DEPTH` | `main.cpp` 的门障碍物生成部分 | 1000.0 | 内开门的占用深度（单位：mm）。对应题目中"1×1 空间" |
| 角度搜索顺序 | `PlacementManager.cpp` 的 `tryPlace` 函数 | {0°, 90°} | 尝试角度的顺序。先试的角度优先级更高 |

### 参数调整建议

- **追求精度**：把 `SEARCH_STEP` 调到 10 或 20，但速度会慢很多
- **追求速度**：把 `SEARCH_STEP` 调到 100 或 200，适合快速验证
- **冰箱开门要留更大空间**：调大 `MIN_GAP`
- **门更大/更小**：调整 `DOOR_DEPTH`

## 10. 算法优缺点

### 10.1 优点

| 优点 | 说明 |
|------|------|
| **简单可靠** | 轴对齐矩形 + 网格搜索，逻辑清晰，容易调试 |
| **效率可控** | 搜索步长可调，普通房间几秒就能跑完 |
| **约束易扩展** | 加新约束只要在 canPlace 里加一关检查 |
| **支持凹多边形** | rectInsidePolygon 的边相交检测能正确处理凹房间 |

### 10.2 局限

| 局限 | 说明 |
|------|------|
| **只支持 0°/90°** | 不能放任意角度的物品 |
| **贪心不是最优** | 找到第一个可行位置就放，不一定是整体最优布局 |
| **搜索顺序固定** | 从左下角开始，可能错过更合理的位置 |
| **单房间单楼层** | 不支持多房间、多层布局 |

## 11. 扩展方向

### 11.1 算法优化

- **智能优化算法**：换成遗传算法、模拟退火，搜索全局最优布局
- **靠墙优先**：搜索时优先贴墙放置，更符合实际装修习惯
- **通道约束**：保证物品之间留有过人的通道宽度
- **任意角度**：支持 0~360° 旋转，几何检测换成 SAT（分离轴定理）

### 11.2 功能扩展

- **可视化**：用 Qt / OpenGL / SFML 把摆放结果画出来，直观查看
- **交互式调整**：支持手动拖拽调整物品位置，实时显示冲突
- **多房间布局**：支持多个房间、走廊、门洞的整体布局
- **物品分类摆放**：同类物品放在一起，功能分区
- **成本/评分函数**：给每个布局打分，选最优的

### 11.3 工程优化

- **空间分区**：用四叉树/网格加速碰撞检测
- **多线程**：多个物品的搜索并行化
- **增量更新**：移动一个物品时，只重新检查相关的碰撞
